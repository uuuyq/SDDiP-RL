# DeepSet-Based Bundle Method RL 模块架构设计

---

## 一、模块概述

本模块实现了基于 DeepSets（集合学习）的 Bundle Method 强化学习框架，用于求解随机双线性规划问题（SDDiP）的对偶优化。核心思想是将 Bundle 中的多个 cutting plane 视为无序集合，通过独立门控机制学习最优的权重组合策略。

### 1.1 核心目标

- 利用 DeepSets 集合学习特性处理可变数量的 cuts
- 通过独立门控机制（Sigmoid）替代 Softmax，消除权重竞争
- 实现线性复杂度的 cut 选择机制
- 学习最优的对偶点更新策略

### 1.2 与 Attention 架构对比

| 对比维度 | Attention 实现 | DeepSet 架构 |
|---------|---------------|-------------|
| **范式** | Transformer 自注意力 | DeepSets (集合学习) |
| **权重计算** | Softmax (归一化竞争) | Sigmoid (独立门控) |
| **顺序敏感性** | 对序列顺序敏感 | 顺序无关（集合特性） |
| **计算复杂度** | O(K²) | O(K) |
| **可变长度** | 需要 padding + mask | 天然支持 |
| **多头机制** | 支持多视角 | 单一查询向量 |

### 1.3 DeepSet 核心优势

1. **独立门控**：多个有用的 cut 可以同时获得高权重，不存在 Softmax 的竞争抑制
2. **线性复杂度**：O(K) 复杂度在 K 较大时效率显著更高
3. **集合特性**：天然支持集合数据，不依赖元素顺序
4. **动态可变**：理论上可以动态调整 cuts 数量

### 1.4 技术栈

| 组件 | 技术/框架 | 版本要求 |
|------|----------|----------|
| 深度框架 | PyTorch | >= 2.0 |
| RL 框架 | Stable-Baselines3 | >= 2.0 |
| 环境接口 | Gymnasium | >= 0.29 |

```
│   │  (MLP φ)     │   │  (MLP q)    │   │  (MLP k)     │                │

│   └──────┬───────┘          │                 │                        │

│                         │                    │                        │

│                          │                                             │
│                          ▼                                             │
│                   ┌──────────────┐                                     │
│                   │score_i = q^T k_i/sqrt(d)│                          │
│                   │w_i = sigmoid(score_i)   │                          │
│                   └──────────────┘                                     │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3.2 数据流分析

#### 3.2.1 输入数据

| 输入项 | Shape | 含义 |
|--------|-------|------|
| `cuts` | (batch_size, K, state_dim) | K个cut的次梯度向量（仅 g_i） |
| `valid_mask` | (batch_size, K) | 有效cut的掩码 |
| `pi` | (batch_size, state_dim) | 当前对偶点 |
| `trial_point` | (batch_size, trial_point_dim) | 试验点特征 |
| `realization` | (batch_size, realization_dim) | 场景数据特征 |

#### 3.2.2 输出数据

| 输出项 | Shape | 含义 |
|--------|-------|------|
| `cut_weights` | (batch_size, K) | 各cut的权重（Sigmoid输出） |
| `eta` | (batch_size, 1) | 步长（0~1） |

### 3.3 状态转移流程

```
action = [w₁, w₂, ..., w_K, η]
       │
       ▼
┌─────────────────────────┐
│ 1. w 通过 Sigmoid 映射  │
│ 2. 使用 mask 过滤无效 cut│
│ 3. 合成方向 d = Σw_i·g_i│
│ 4. 更新 π ← π + η·d     │
│ 5. 求解子问题得到新 cut │
│ 6. 计算 Log-Gap Reward  │
└─────────────────────────┘
```

## 四、核心组件详解

### 4.1 Encoder 模块

#### 4.1.1 CutEncoder

```python
class CutEncoder(nn.Module):
    # 输入: g_i (state_dim,)
    # 输出: h_i (hidden_dim,)
    # 结构: Linear → ReLU → Linear → ReLU
```

#### 4.1.2 QueryNetwork

```python
class QueryNetwork(nn.Module):
    # 输入: z_g = [h_g, pi, trial_point, realization]
    # 输出: q (query_dim,)
    # 含义: "当前优化状态需要什么方向？"
```

#### 4.1.3 KeyNetwork

```python
class KeyNetwork(nn.Module):
    # 输入: h_i (hidden_dim,)
    # 输出: k_i (key_dim,)
    # 含义: "这个cut能提供什么信息？"
```

#### 4.1.4 DeepSetBundleEncoder（完整编码器）

```python
class DeepSetBundleEncoder(nn.Module):
    # 整合 CutEncoder + MeanPooling + QueryNetwork + KeyNetwork
    # 输出: cut_weights, z_g (供 EtaHead 使用)
```

**编码流程**：
1. CutEncoder 编码每个 cut → h_1, h_2, ..., h_K
2. Mean Pooling → h_g = Mean(h_1, ..., h_K)
3. 拼接全局特征 → z_g = [h_g, pi, trial_point, realization]
4. QueryNetwork → q
5. KeyNetwork → k_1, k_2, ..., k_K
6. 计算权重 → score_i = q^T k_i / sqrt(d), w_i = sigmoid(score_i)

### 4.2 EtaHead

```python
class EtaHead(nn.Module):
    # 输入: z_g (全局特征)
    # 输出: eta (batch_size, 1), 范围(0, 1)
    # 使用 sigmoid + scale 超参数
```

## 六、关键设计决策

### 6.1 为什么使用 Sigmoid 而非 Softmax？

1. **独立门控**：每个 cut 的权重独立计算，不存在竞争抑制
2. **可变数量**：天然支持动态调整 cuts 数量
3. **稀疏激活**：可以有多个高权重 cut，也可以所有 cut 权重都很低

### 6.2 为什么使用 Mean Pooling？

1. **集合特性**：Mean Pooling 是 DeepSets 的标准操作
2. **顺序无关**：满足集合的无序性要求
3. **计算高效**：O(K) 复杂度
